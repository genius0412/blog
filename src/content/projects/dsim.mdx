> DSIM is a browser-based robotics driving game built around the FIRST Tech Challenge *DECODE* game. I founded it and write most of the code: the simulation, the networking, the ranked backend, and the interface.

Two drivers face off online, 1v1 or 2v2, matched by skill. A Node WebSocket server is authoritative — it runs the match and streams delta-encoded snapshots at 30 Hz, so both clients stay in sync and the server stays the single source of truth.

Underneath that is the simulation, a pure state machine that takes per-tick robot commands and a seeded PRNG and never touches the DOM or the clock. Keeping it deterministic and serializable is what makes the authoritative netcode, the saved replays, and the test suite possible at all. Rendering, input, and the React UI sit on top, and the physics and scoring already generalize across different robot counts and game modes.

Matches feed a Glicko-2 ladder, the same system chess.com uses, where a rating carries a deviation instead of being a single number. Seasons, per-game leaderboards, friends, live presence, and match history are persisted in Postgres on Neon.

There's a headless test suite of 527 tests covering spawn layout, drive kinematics, scoring and penalties, match phases, and the multiplayer room lifecycle. All of them currently pass. The sim, netcode, server, and UI come to roughly 39,000 lines of TypeScript and React.

The stack is TypeScript, React, and Vite on the front end, Rapier2D for physics, a Node WebSocket server, Postgres on Neon for ranked play and accounts, and an Electron build for desktop.
